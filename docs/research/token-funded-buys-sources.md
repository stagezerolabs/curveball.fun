# Token-funded curve buys: source notes

Researched 2026-10-08. These are implementation constraints for the proposed ERC-20 → WETH → curve-buy path, not a claim that a particular swap venue is deployed on RISE Testnet.

## Findings

- **The backend can quote and prepare a transaction; it cannot swap a user's tokens by itself without custody or a user-approved on-chain transfer.** ERC-20 `transferFrom` spends an allowance granted by the owner. A noncustodial flow therefore needs the user to approve a spender (or sign a supported permit), then execute an on-chain swap. [OpenZeppelin ERC-20 interface](https://docs.openzeppelin.com/contracts/5.x/api/token/erc20#IERC20-transferFrom-address-address-uint256-), [Uniswap Permit2 overview](https://developers.uniswap.org/docs/protocols/permit2/overview).
- **The swap needs a real route and liquidity.** Uniswap v3 `exactInputSingle` swaps a fixed token input for as much output as the selected pool provides; the example warns that a contract swap needs an external price source to avoid serious front-running loss. The production path must enforce minimum WETH output, a deadline, and a separate minimum curve-token output; the backend quote is only an estimate. [Uniswap v3 single swaps](https://developers.uniswap.org/docs/protocols/v3/guides/swapping/single-hop-swapping).
- **Curveball already uses WETH as its curve quote asset.** Its current `buyTokens` pulls the ERC-20 quote with `safeTransferFrom`; a USDC→WETH route should pass WETH directly to the curve, with no unwrap step. Native ETH is needed separately for gas. The Universal Router can compose wrapping and unwrapping, but its existence on one network says nothing about its deployment on RISE Testnet. [CurveBondingCurve.sol](../../contracts/contracts/CurveBondingCurve.sol), [Uniswap Universal Router overview](https://developers.uniswap.org/docs/protocols/universal-router/overview).
- **Approvals are a separate UX and security choice.** Permit2 requires a token approval to the Permit2 contract first; then its `SignatureTransfer` offers one-time signed transfers and `AllowanceTransfer` supports amount- and time-limited spending. ERC-2612 works only when the token implements it, and OpenZeppelin notes smart-contract wallets may not produce permit signatures, so retain a plain approval path. Do not assume Permit2 is deployed on RISE Testnet because its familiar address is documented only for Uniswap-supported chains. [Uniswap Permit2 overview](https://developers.uniswap.org/docs/protocols/permit2/overview), [OpenZeppelin ERC-20 permit notes](https://docs.openzeppelin.com/contracts/5.x/api/token/erc20#ERC20Permit).
- **Contract composition needs explicit guards.** `SafeERC20` handles ERC-20 implementations that return false or no value; `ReentrancyGuard` prevents nested calls into guarded entry points. For a swap-and-buy adapter, allowlist token and router addresses, validate that the token and swap outputs are received, and avoid leaving ERC-20 or ETH dust trapped in the adapter. The latter design rules are recommendations inferred from external token/router calls and Uniswap's warning that failed partial router commands need cleanup. [OpenZeppelin SafeERC20](https://docs.openzeppelin.com/contracts/5.x/api/token/erc20#SafeERC20), [OpenZeppelin ReentrancyGuard](https://docs.openzeppelin.com/contracts/5.x/api/utils#ReentrancyGuard), [Uniswap Universal Router overview](https://developers.uniswap.org/docs/protocols/universal-router/overview).
- **The Uniswap route is unverified for RISE Testnet.** Uniswap's published Trading API supported-chain list does not list RISE; RISE's faucet says it offers test ETH, WETH, USDC and other tokens, but that does not establish a liquid USDC/WETH pool or a compatible router. RISEx public testnet documentation describes a perps orderbook, not a verified spot AMM swap route. Before selecting a router, verify its deployed address, code, pool reserves, quote behavior, and token addresses on the exact testnet chain. [Uniswap supported chains](https://developers.uniswap.org/docs/trading/swapping-api/supported-chains), [RISE faucet](https://faucet.risechain.com/), [RISEx public testnet guide](https://blog.risechain.com/risex-public-testnet-guide/).

## Testnet implication

A mock ERC-20 alone cannot demonstrate a swap. The testnet prototype also needs a funded mock-token/WETH liquidity source (or an intentionally scoped mock swap contract with a funded WETH reserve). If an actual RISE Testnet spot venue is found, verify its contracts and test the entire atomic route. Keep the existing ETH/WETH buy path available while the new token path is developed.
