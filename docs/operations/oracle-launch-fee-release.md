# Oracle launch fee and full mainnet reset

## Scope and release state

This release targets RISE mainnet chain 4153. The operator broadcast the oracle launchpad and adapter from the `dot` Foundry keystore; no smoke token was launched. The verified launchpad is `0xC2C337301303d8bE4803042425aA5A325d30e6d7` and its adapter is `0x01d06FE7D91Af00eFd3D559B9B2B943756cBd797`. The old launchpad continues to exist onchain; old markets are excluded from the new app and indexer. The reset intentionally deletes all local production database rows, including accounts, profiles, follows, market records, trades, candles, notes, notifications, and indexer cursors. It also deletes the production Postgres backup volume. An external/off-host copy, if one exists, must be handled separately.

## Oracle selection and heartbeat

Curveball reads the [Stork RISE mainnet proxy](https://docs.stork.network/resources/contract-addresses/evm#rise) at `0xacC0a0cF13571d30B4b8637996F5D6D774d4fd62` directly. The ETH/USDC feed ID is `0x7965e1bfc07a34caf0c3aa8146b200264fbb7a0eb85b1d3b1fdceecffd736b02`. Stork [lists ETHUSDC on RISE mainnet](https://docs.stork.network/resources/stork-pushed-assets) with a 0.5 second maximum push trigger. The [checked EVM read](https://docs.stork.network/api-reference/contract-apis/evm) has its own chain-dependent stale threshold, typically 3600 seconds. Curveball imposes a 1800 second limit as well. This gives a generous interruption window while still stopping launches if prices cease updating. The window is checked again in the launch transaction. Existing market trades and fee claims do not depend on the oracle.

The [RISE internal oracle page](https://docs.risechain.com/docs/builders/mainnet-internal-oracles) documents `RISExOracle` and `RISExStork`, which are distinct from the Stork EVM proxy selected for this fee. Its `getIndexPrice` example does not expose a timestamp in that interface, so the Curveball fee path uses the Stork timestamped feed.

Run `make oracle-status-mainnet` before broadcast and after recording. It reads the Stork feed and, when the v3 record exists, checks that the deployed launchpad uses the expected oracle, age limit, and $1 arithmetic. It sends no transaction. An unavailable feed keeps launching closed; do not introduce a fixed fee or cached price fallback.

## Operator sequence

1. In the local checkout, commit the contract source and run `make preflight-mainnet-dot`. It requires chain 4153, tests, strict mainnet fork tests, Icarus verification, a clean contract tree, and a dry run with the pinned `dot` address. `RISE_MAINNET_RPC_URL` may be set in ignored `.env`; otherwise targets use the public RISE RPC.
2. In your own shell, run `make deploy-mainnet-dot`. Foundry prompts for the `dot` keystore password and broadcasts only the timelock and Curveball singletons. It does **not** launch a token. Run `make record-mainnet-dot` after explorer source verification. This creates `deployments/4153/curveball-oracle-v3.json` and checks receipts, source, runtime bytecode, fee math, Stork wiring, the 1800 second age limit and roles.
3. Run `make deploy-swap-mainnet-dot`, then `make record-swap-mainnet-dot`. The adapter is tied to the newly recorded launchpad. Both deploy targets are separate so a failed record never silently advances the next onchain step.
4. Run `make configure-mainnet-dot`, inspect `.env.production` and ignored service envs, and publish the source, new records, and tracked configuration to the production checkout. Follow [the deployment file transfer procedure](../../.codex/DEPLOYMENT.md); protect existing secrets. On the VPS run `make configure-mainnet-host` to update the existing generated `deploy/*.env` files without replacing secret values. Verify `docker compose --env-file deploy/production.env -f compose.production.yaml -f deploy/compose.mainnet.yaml config --quiet`.
5. On the VPS, from `/opt/curveball-mainnet`, run `make reset-mainnet-database CONFIRM_RESET=DELETE_ALL_CURVEBALL_MAINNET_DATA`. This checks chain/record/env parity, builds API and keeper images, stops the mainnet stack, deletes the named data and backup volumes, and restarts Compose. The `migrate` job creates the new schema before API starts. This action is irreversible for data stored only in those volumes.
6. Confirm API and both edge containers are healthy, the market list has no old markets, profiles are empty until new sign-ins, and the indexer starts from the v3 deployment block. Run `make oracle-status-mainnet` and read the launch form to confirm the live fee and cap. No smoke token, buy, or other market transaction is required.

If the oracle becomes stale during cutover, the launch form and `launch` call fail closed. The app can still show markets and allow existing market trading. If source verification or config parity fails before the reset, keep the prior production stack running and resolve the failed gate. After the full reset, a rollback to the old app would require a separately retained external database snapshot; the old onchain contracts themselves remain accessible independently of the app.
